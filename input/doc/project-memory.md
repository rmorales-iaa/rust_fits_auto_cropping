## Persistent user and science contracts

- Classification depends on pixel statistics and geometry only. Structural/scaling/null metadata is necessary for decoding; WCS metadata is necessary for output preservation. Descriptive header values do not steer the detector. Evaluation groups may use instrument/night metadata without making it a classifier feature.
- Process eligible single-HDU 2D images; compressed/multi-HDU and malformed inputs are not classified, but normal runs preserve every discovered FITS path as exactly one `images/` entry. Unsupported and malformed inputs are annotated and passed through as canonical-source symlinks. No resampling or source intensity modification beyond explicit exclusion. Preserve raw retained samples and original observations.
- Maximize valid science retained and true artifact area removed under a declared valid-loss and source-preservation budget. A larger mask is not inherently better. Candidate artifacts, original undefined samples, uncertain boundaries and geometric sacrifice are different quantities.
- Mask mode remains the default. Crop mode selects the exact global maximum-area axis-aligned rectangle over the combined detector-exclusion and originally undefined-pixel mask. There is no circular geometry constraint. Products contain no excluded or originally undefined pixels, `NAXIS1/2` match output dimensions, and supported CRPIX cards shift by crop origin. Crop mode also has a configurable hard cap on unmasked geometric sacrifice as a fraction of defined non-artifact pixels, selected by accepted border-touching component count (25/30/35/41% for one/two/three/four-or-more areas); beyond it the source is kept unchanged. This is a conservative provisional safeguard, not a calibrated science-loss model.
- Regression for `science#2007_01_11T20_57_04...`: current rectangle at `(336,144)`, `1040×1296` / 1,347,840 pixels, versus the superseded circle-constrained `1085×1085` / 1,177,225 pixels; output keeps 170,615 additional pixels. Release `0.1.64` passed Rust/Clippy/format checks and Astropy/fitsverify plus all 16 preview checks on the 25-file development set. See [validation evidence](validation.md). This does not close the independent science-label gate.
- Kept eligible images and unsupported/malformed pass-throughs are canonical source symlinks. Generated products carry version/time provenance and checksums. Preserve source headers through kept links.
- Each invocation uses `<output>/runs/<run-id>/` for images, masks, previews, reports and ISO activity logging. Validate output paths and overlap; preserve prior runs and unrelated files. Build state is ignored under `output/.state/`.
- Keep bounded concurrency, separate runtime/science TOML, small modules and coherent local commits. Do not claim actual memory bounds or scientific accuracy from estimates or passing unit tests alone.

1. Freeze reproducible baseline and regression fixtures; fix numerical/sentinel/FITS/header/WCS/reporting/publication failures before algorithm promotion.
2. Obtain independently labeled data with group splits, uncertainty labels and a registered observing domain. Develop source-aware local reference/noise estimation, multiscale residual evidence, component decisions and pixel-boundary refinement.

4. Profile actual stage buffers, sorts, copies and reads; optimize exact algorithms/ownership first and validate weighted memory scheduling. Repeat release benchmarks with paired workloads and unchanged science gates.
5. Freeze thresholds on development/calibration groups, then use untouched groups and independent science/FITS/WCS checks. Proposed numeric targets in the active plan are requirements to justify and register, not achieved accuracy.
6. Stop planning after two full reviews find no new material omission; stop algorithm complexity only after bounded development experiments establish negligible practical gain with adequate uncertainty. Insufficient statistical power is not evidence of equivalence.

## Optional pixel-action reason plane

- The opt-in `--reason-mask` flag writes a single-HDU uint8 FITS sidecar under `reason_masks/<input-relative-path>` for applied mask/crop actions. `RSCHEME=PIXACT1`: 0 retained defined pixel, 1 detector-selected artifact pixel excluded, 2 defined pixel excluded only by crop geometry, 3 pre-existing undefined pixel. Code 3 wins precedence. These are program-action records, not ground-truth validity or calibrated probabilities.
- Report schema 7 carries the optional path; version-3 completion manifests SHA-256 every product, including the reason plane. Rust write verification checks shape, byte codes, scheme card and FITS data checksum. The independent Python checker additionally verifies reason codes exactly partition defined action-mask exclusions and original undefined pixels, source geometry, WCS cards and metadata preservation. Its 12 unit tests pass, as does Astropy/fitsverify over the requested 25-file corpus output. FITSFixedWarnings identify legacy source WCS/time cards; several SIP inverse transforms do not converge although sampled forward transforms match. This feature does not resolve P2–P7 or certify scientific performance.

## Header metadata must not skip decodable pixels — 2026-10-28

A review found that lookup-table/distortion WCS metadata caused crop mode to symlink a detected image unchanged. This is now a dimension-preserving mask fallback: the metadata limitation is included in the per-file summary, detector evidence still comes only from pixels, and accepted detections are applied while preserving the original coordinate grid. `crop_wcs_mask_fallback` identifies that action. Structurally unsupported inputs (compressed/multi-HDU and non-2D) remain excluded under the explicit input contract; malformed FITS remains an annotated passthrough because it cannot be decoded safely. End-to-end regression now asserts a valid image with CPDIS metadata is actually processed and its detected pixels are marked undefined.
