# Initial border detector

The current detector is an engineering baseline for large, border-connected regions. It divides a two-dimensional image into square tiles. For each tile it measures the finite-sample median and scaled median absolute deviation. It estimates the image interior from central tiles, then compares each tile median with the median of those interior medians. Its contrast score divides the absolute difference by the larger of the robust tile-median dispersion, interior noise scale and a small relative numeric floor.

It also measures horizontal and vertical lag-one Pearson correlations from finite adjacent pixel pairs. Correlation supports an already high-contrast tile; it is never sufficient alone. For a constant tile, correlation is undefined. A zero-dispersion region against a measurable zero-dispersion interior may still be selected if it has clear contrast. The detector grows 4-connected candidate components from each frame edge and preserves isolated interior components. It expands accepted tile selections to whole tiles, then applies configured minimum/maximum tile-area fractions.

The detector supports asymmetric and partly symmetric regions through the connected-component mask. Decisions use image pixel statistics and mask geometry; object names, instrument labels, WCS values and other descriptive FITS cards are not detector evidence. FITS shape, storage/scaling and null-value cards are still needed to decode samples. Circle and rectangle selection happens after pixel-statistics detection: crop mode compares the largest all-unmasked rectangle against the largest artifact-free circle and uses the one containing more unmasked pixel centers. A circular result is stored in its bounding box with exterior samples marked undefined. The circle is a geometric summary of the detected mask, not an instrument header prior. A configured utility gate weighs artifact removal against unmasked pixels sacrificed and keeps the source when the sacrifice is not justified. Tile-based mask boundary precision is limited by `tile_size`.

FITS structural cards are needed to decode dimensions, storage type, and HDU count; `BSCALE/BZERO` are used to interpret stored pixel values. Instrument, observation, and WCS metadata do not contribute to detection scores or geometry choice. An out-of-range `BLANK` card is ignored for pixel statistics and replaced/removed in derived products as appropriate; valid in-range `BLANK` samples retain FITS undefined semantics.

A score is not a p-value or probability: spatial pixels and tiles are dependent, detector thresholds have not been calibrated, and selecting the center as reference can fail when the usable field is off-center. Noise reduction and correlation can also occur in valid sky or astronomical structure. Ambiguous outputs should be retained by raising the contrast gate or lowering the maximum mask fraction. Never interpret this baseline as proof that masked pixels contain no science signal.

## Optional crop preview

With `--mode crop --png`, each accepted crop receives a side-by-side grayscale PNG. The renderer estimates a ZScale interval from up to 1,000 finite, regularly strided source samples, using Astropy/IRAF-style 0.25 contrast, 2.5-sigma rejection and five-iteration defaults. The same interval maps both panels, so crop values can be compared directly with their source locations. Panels retain native pixel scale and lower-origin FITS orientation; invalid values and samples outside a circular crop are black. PNG intensity is a visualization only and does not affect detection, crop geometry or FITS sample values.
