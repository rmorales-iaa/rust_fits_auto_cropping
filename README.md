# rust_fits_auto_cropping

A conservative Rust CLI prototype that detects large, anomalous regions connected to the borders of one-HDU, two-dimensional FITS images. It writes processed images with accepted samples marked undefined, a separate mask, symlinks unchanged images into the output tree, and creates a per-run report. Original files remain untouched. Detection is driven by pixel statistics; non-structural header content is not a detector feature.

The first detector uses robust tile statistics, spatial lag-one correlation and border-connected components. It supports asymmetric and partly symmetric border patterns; circle/rectangle boundaries are approximated at tile scale. Its thresholds are starting values and have **not** been scientifically validated against held-out observatory images. Inspect every mask before scientific use. See [the algorithm and its limits](input/doc/algorithm.md).

The [scientific audit](input/doc/scientific-audit-2026-10-27.md) found boundary over/under-removal, numerical scaling and integer-sentinel failures, and metadata/reporting gaps despite 47 passing tests. Follow-up fixes include conservative keep-source fallback when no integer BLANK value is available, dimension-preserving mask fallback when lookup-table/distortion WCS prevents a safe crop, integer precision abstention, independent component gates, rescaled allocation-free correlation, exhaustive small-grid geometry oracles, source-byte digests, stable decision codes, and explicit C/A/E/U0 set accounting. Schema-9 reports include total and output-image counts plus the optional reason-plane path; the prior schema-6 accounting distinguishes candidate, proposed, applied-artifact and crop-geometry sets, including their intersections with original undefined pixels. The current source snapshot is carried from detection through output writing so classification, serialization and verification use one parsed input; per-image reports include source SHA-256 digests; per-input completion markers are not generated. The opt-in `--reason-mask` product records retained pixels, detector-selected artifact exclusions, crop-only sacrifices and pre-existing undefined samples. Its codes are action bookkeeping, not ground-truth science labels. These are engineering improvements, not scientific validation: tile-scale boundary error remains, a source-aware local model and pixel refinement remain unimplemented. The opt-in robust-affine reference and multiscale-consensus detector are experimental; thresholds have no independent calibration. See the [active improvement plan](input/doc/scientific-improvement-plan.md) and [validation record](input/doc/validation.md). Cargo package version `0.1.0` and the machine-local `--version` build counter identify different things; neither is a scientific certification.

## Build and run

Requires Rust 1.88+. FITS reading and writing use the pure-Rust [`fitskit`](https://docs.rs/fitskit/) crate and do not require CFITSIO or a system C library.

```bash
cargo build --release
cargo run --release -- --input-dir input/data --output-dir output --config input/config.toml
cargo run --release -- --input-dir input/data --output-dir output --recursive --config input/config.toml --heuristics input/heuristics.toml
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --recursive
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --flat-output --recursive
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --png --recursive
cargo run --release -- --input-dir input/data --output-dir output --dry-run
```

Pass `--help` for options, examples, crop semantics and exit codes. `--version` reports the build counter. The output root is canonicalized and checked before use; a symlinked root, overlapping input/output trees, unsafe relative destinations or symlinked managed subdirectories are rejected. Previous run data are preserved unless `--sanitize-output` is explicitly selected. By default only the immediate input directory is searched; use `--recursive` for nested folders. Multi-HDU files, unsupported shapes and compressed inputs remain ignored because their pixel arrays are not accepted by the current processing contract. A valid decoded image is always checked by pixel statistics regardless of descriptive/WCS header cards. Source header cards are never repaired: malformed non-structural cards are substituted only in the parser's temporary in-memory view, annotated in the summary, and copied byte-for-byte into generated FITS products while pixels are processed. Crop dimensions and product provenance are updated as required, but those operations do not normalize malformed source cards. Structural layout cards such as BITPIX and NAXIS must remain readable to locate pixel data. If lookup-table WCS prevents a safe rectangular crop, the summary records that metadata limitation and accepted border detections are applied as a dimension-preserving full-frame mask. Inputs with unreadable structural layout or those exceeding the configured memory limit are recorded as errors. In normal runs, every discovered FITS path has one corresponding image product: under `images/` by default or directly under the output root with `--flat-output`. Malformed structural files and ignored inputs are annotated and passed through as symlinks to their originals. Dry-run writes no image entries.

## Yearly calibrated-image workflow

[`scripts/process_cropped_years.sh`](scripts/process_cropped_years.sh) creates `/mnt/uxmal_groups/image_storage/cropped/<year>/`, links the `bias/`, `dark/`, and `flat/` directories from `rust_om_cal`, and processes `science_calibrated/` recursively in crop mode with PNG previews enabled. Before each year run, `--sanitize-output` clears the contents of only its dedicated `science_calibrated/` destination. FITS products and reports go directly under that path; previews remain in its `previews/` directory, with no `images/` or `runs/<run-id>/` layer for current products. Test one year with `scripts/process_cropped_years.sh --year 2002`; with no arguments it processes years 2002 through 2026. Existing non-symlink calibration destinations and links that point elsewhere are left untouched and reported as errors.

## Products and configuration

Image processing is parallelized with a bounded Rayon worker pool. Set `processing.threads` in `input/config.toml` to `4` (default) or `0` to request all logical CPUs available to the process; CPU and memory limits can reduce the effective count. The activity log records the effective number of workers.

By default each run is stored beneath `output/runs/<run-id>/` with science images in `images/`. `--flat-output` writes science images directly under the given output directory instead, for workflows that require a fixed destination such as `/mnt/uxmal_groups/image_storage/cropped/2002/science_calibrated/`; previews remain in `previews/`, and reports and logs remain in the root. `--sanitize-output` explicitly deletes every existing entry in the output root before processing, and is used by the yearly workflow only on its dedicated science-output directory. `previews/` is optional and created only when `--png` is enabled and a crop is accepted. There is no `manifests/` directory or per-input completion marker; the final summary and activity log record per-input decisions and output paths. Temporary `masks/` and `reason_masks/` work directories are removed before reports are written and before exit. `summary.json` reports `total` discovered inputs and `output_images` published image entries; for a successful normal run these counts match. Previous run directories are preserved in the default layout unless `--sanitize-output` is explicitly selected. Output-root symlinks, input/output overlap, unsafe relative paths and symlinked product subdirectories are rejected before product writes. Output symlinks target canonical input files and preserve original bytes and headers. Generated FITS products record program/version in `CREATOR`, UTC product date in `DATE`, and generation time in bounded `HISTORY` cards. The tracked `input/program-version.txt` template begins at `0.0.0`; each Cargo package recompilation increments the build version in base 100. Mask mode preserves dimensions. Crop mode (`--mode crop`) writes the exact maximum-area axis-aligned rectangle containing no detector-proposed artifacts or originally undefined samples. It maximizes the rectangular pixel area retained under the detected exclusion mask; results are not constrained by a circular fit. Accepted crop FITS filenames add `_cropped` before the extension; kept and pass-through images keep their original names. FITS `NAXIS1/2` match the selected rectangle width and height, and supported primary/alternate `CRPIX1/2` values shift by the crop origin. The configured utility remains provisional and is not a calibrated science loss model.

| Accepted border-connected areas | Maximum unmasked area sacrificed |
| ---: | ---: |
| 1 | 35% |
| 2 | 35% |
| 3 | 35% |
| 4 or more | 47% |

Each counted area touches at least one image edge; one component touching multiple edges counts once. The utility gate can also keep a proposed crop. Integer image pixels use FITS `BLANK` when a representable value is available; float pixels use NaN. Retained raw samples and checksums are verified against the same parsed FITS snapshot used for detection.

Reports distinguish edge-tile candidate support (`candidate_mask_pixels`), accepted proposals (`proposed_mask_pixels`), and applied artifact exclusions (`applied_artifact_pixels`). `masked_pixels` includes all newly excluded defined samples, including crop-only geometric sacrifices. `crop_excluded_undefined_pixels` records originally undefined samples inside the proposed crop exclusion; it is kept separate from both scientific artifact removal and sacrificed defined pixels. Schema 9 records input/output counts, candidate/proposed/applied intersections with original undefined pixels, candidate/proposal overlap, crop geometry intersections, and proposed-versus-applied crop accounting. Stable `reason_code` values support machine-readable decisions alongside explanatory text. Dry runs set the top-level `dry_run` flag and report zero applied exclusions and zero output images. Independent artifact labels and science validation remain future work.

Previews are disabled by default. With `--mode crop --png`, `output/runs/<run-id>/previews/<input-relative-path>.png` is written for each accepted crop. Each RGB preview places the complete grayscale input at left and the unchanged grayscale crop at right using independent ZScale intervals computed from the full input and the exact final cropped FITS samples, labeled panels and FITS lower-origin orientation. The crop panel is uniformly scaled with nearest-neighbor sampling to fill its display height while preserving aspect ratio; its `CROP FIT` label marks that its displayed pixel scale can differ. A green line outlines the pixels retained by the crop; a red line marks the adjacent excluded/cropped pixels on the left panel. The crop panel contains only the crop image; no blank canvas rows are added. Previews are diagnostic only; the FITS output remains the science product, and each preview path appears in the report.

Pass `--reason-mask` to build and verify a temporary byte image for each accepted mask/crop action. Its containing `reason_masks/` directory is removed before the run completes, so no sidecar path or checksum is published. Codes `0` retained defined sample, `1` detector-selected artifact exclusion, `2` crop-only sacrifice of a defined sample, and `3` originally undefined sample. Undefined samples take precedence. The temporary sidecar preserves compatible WCS cards and has `RSCHEME=PIXACT1`. These codes describe program actions, not astrophysical validity or calibrated confidence.

Operational settings live in [input/config.toml](input/config.toml), and science decision rules live in [input/heuristics.toml](input/heuristics.toml). Read the [user guide](input/doc/user-guide.md), [configuration reference](input/doc/configuration.md), [architecture](input/doc/architecture.md), [algorithm limits](input/doc/algorithm.md), [build and provenance policy](input/doc/release-and-provenance.md), [validation record](input/doc/validation.md), and [project memory](input/doc/project-memory.md). Crop mode is opt-in and can discard unmasked science pixels; check each report before downstream use. Gzip-compressed and multi-HDU inputs are ignored.

## Project development

Source code is organized in small modules under `src/`; tests are under `tests/`. Run `cargo test --all-targets`, `cargo fmt --all --check`, and `cargo clippy --all-targets -- -D warnings`. The independent FITS checker is `tools/cross_validate_fits.py`; it requires Astropy and runs `fitsverify` when available. It audits retained science images, reports, preserved/added FITS cards, and primary/alternate WCS; transient action-mask sidecars are intentionally absent after a run. Run its Python regression tests with `python3 -m unittest tools/test_cross_validate_fits.py`. `tools/cross_validate_previews.py` requires Astropy and Pillow to validate PNG scaling, green/red overlay geometry and colors, orientation and source/crop display samples. Each verified coherent change is registered in local Git. Build products, logs and raw FITS inputs are ignored. A local branch commit does not publish without a configured remote and explicit push.
