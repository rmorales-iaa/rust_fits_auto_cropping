# Architecture

The application keeps CLI parsing, typed configuration, file discovery, FITS access, robust statistics, border detection, output writing, logging and summary generation in separate Rust modules. The algorithm module consumes a row-major floating analysis array and returns a boolean mask plus diagnostics; FITS code has no role in deciding whether a region is scientifically invalid.

The pure-Rust `fitskit` crate parses and serializes FITS files. A header-only preflight seeks over payloads to count HDUs and reject unsupported or oversized files before allocating pixel arrays. Descriptive header values are not detector inputs; structural, storage-scaling and null metadata are interpreted or validated as required by the FITS representation. Scaling cards are not applied to detector statistics. Each accepted file is independently owned by one worker; no shared FITS handles or global FITS lock are needed. Directory jobs run in a bounded Rayon pool, so independent detection and FITS work can overlap. Workers are limited by `memory_budget_mib / maximum_image_mib`; the configured estimate has not been established as a peak-memory upper bound, especially for crop/write/verification/PNG stages. No repeated paired performance benchmark has established an improvement or a hard memory cap.

For integer arrays, `fitskit` exposes stored samples directly. Detection uses median-centered raw integer values formed with i128 differences; it abstains when an integer span cannot be represented exactly in the f64 analysis domain. Floating samples are centered by a finite median with overflow-safe fallback arithmetic. `BSCALE/BZERO` remain in copied science headers but are not applied to detector values. The parsed source `FitsFile` is retained in the `Image` result and is the source for generated products, eliminating later source-path reparsing and ensuring classification, written samples and in-process verification refer to one snapshot. The writer reuses a valid existing integer `BLANK` and otherwise searches for a code absent from retained samples only when a product adds undefined pixels. If no integer code is available, processing keeps the input as an unchanged symlink. Floating exclusions use IEEE NaN. A separate uint8 primary image stores the new mask and copies eligible non-structural source cards, including WCS, while excluding scaling, dimensions, extrema, units and checksum cards. Generated science/mask products receive `CREATOR`, UTC `DATE`, and bounded `HISTORY` entries. Unchanged images are symlinks and preserve source bytes. The crate rewrites parsed headers during serialization, so byte-for-byte card formatting is not promised for generated products. FITS checksums and semantic sample comparisons are verified against the retained snapshot; ordinary failures attempt rollback. Crop mode conservatively keeps the input when lookup-table or recognized distortion metadata cannot be safely shifted. Full WCS support remains open.

Generated science and mask products are written to temporary paths and renamed into place. Unchanged kept images are staged as symlinks on the output filesystem and atomically published; the symlink target is the canonical input path. Parsing and source hashing use the same open file handle: the digest is calculated as fitskit reads the stream, including block padding skipped by forward seeks, with bounded memory. A size/modified-time change during parsing is rejected. After verification and any requested preview, per-input output paths and outcomes are recorded in the run summary and activity log. The application does not create a `manifests/` directory or per-input completion-marker files; consumers should use the final `summary.json` to assess completed outputs. If mask publication fails after science image publication, ordinary error handling rolls back the partial image. Reports are sorted by relative input path so scheduling does not affect their record order.

The initial detector operates on fixed-size tiles. It obtains robust median and MAD summaries, estimates an interior reference, computes allocation-free lag-one spatial correlation with rescaled Welford moments, flags high-contrast tiles supported by correlation or unusually low noise, then labels 4-connected edge components. Each component must independently clear tile-count, area, evidence and provisional utility gates before its tiles are accepted. Final aggregate area and utility checks still apply. Reports record candidate and accepted component counts. Component labeling prevents disconnected regions from borrowing support, but does not provide multiscale evidence, source protection, calibrated statistics, or pixel-level boundaries. Accepted tiles still expand to whole tiles. This remains a first-pass heuristic, not a trained/calibrated classifier; domain-specific validation remains open.

When requested with `--png` in crop mode, a post-decision renderer uses the Rust `image` crate's PNG encoder. It estimates one source-wide ZScale interval and draws labeled native-scale panels under `output/runs/<run-id>/previews/`. Preview paths are included in reports and activity events; rendering does not participate in detection or crop selection.

The default output layout isolates each invocation under `runs/<run-id>/` and stores science images in `images/`. The opt-in `--flat-output` layout sets the run root to the requested output root, stores science image files directly there, and continues to place previews under `previews/`. Reports and the activity log remain at the root. The yearly storage script uses this flat layout for its fixed per-year destination.
