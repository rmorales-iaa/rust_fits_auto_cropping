# Architecture

The application keeps CLI parsing, typed configuration, file discovery, FITS access, robust statistics, border detection, output writing, logging and summary generation in separate Rust modules. The algorithm module consumes a row-major floating analysis array and returns a boolean mask plus diagnostics; FITS code has no role in deciding whether a region is scientifically invalid.

The pure-Rust `fitskit` crate parses and serializes FITS files. A header-only preflight seeks over payloads to count HDUs and reject unsupported or oversized files before allocating pixel arrays. Descriptive header values are not detector inputs; structural, storage-scaling and null metadata are interpreted or validated as required by the FITS representation. Scaling cards are not applied to detector statistics. Each accepted file is independently owned by one worker; no shared FITS handles or global FITS lock are needed. Directory jobs run in a bounded Rayon pool, so independent detection and FITS work can overlap. Workers are limited by `memory_budget_mib / maximum_image_mib`; the configured estimate has not been established as a peak-memory upper bound, especially for crop/write/verification/PNG stages.

For integer arrays, `fitskit` exposes stored samples directly. Detection uses median-centered raw integer values formed with i128 differences; floating samples are centered by a finite median. `BSCALE/BZERO` remain in copied science headers but are not applied to the detector values. The writer reuses a valid existing integer `BLANK` and otherwise searches for a code absent from retained samples only when a product adds undefined pixels. Floating exclusions use IEEE NaN. A separate uint8 primary image stores the new mask and copies eligible non-structural source cards, including WCS, while excluding scaling, dimensions, extrema, units and checksum cards. Generated science/mask products receive `CREATOR`, UTC `DATE`, and bounded `HISTORY` entries. Unchanged images are symlinks and preserve source bytes. The crate rewrites parsed headers during serialization, so byte-for-byte card formatting is not promised for generated products. FITS checksums and semantic sample comparisons are verified after writing; ordinary failures attempt rollback. Unsupported WCS handling and a complete transactional publication guarantee remain open work.

Generated science and mask products are written to temporary paths and renamed into place. Unchanged kept images are staged as symlinks on the output filesystem and atomically published; the symlink target is the canonical input path. The published science output is reopened to check one HDU, dimensions/BITPIX, retained samples, null representation and data sums. A process interruption can occur before this post-publication validation or pair rollback completes. If mask publication fails after science image publication, the partial image is removed. Reports are sorted by relative input path so scheduling does not affect their record order.

The initial detector operates on fixed-size tiles. It obtains robust median and MAD summaries, estimates an interior reference, computes lag-one spatial correlation, flags high-contrast tiles supported by correlation or unusually low noise, then flood-fills only edge-connected candidates. A mask is accepted only when it clears area and total-fraction gates. This is a first-pass heuristic, not a trained/calibrated classifier; domain-specific validation remains open.

When requested with `--png` in crop mode, a post-decision renderer uses the Rust `image` crate's PNG encoder. It estimates one source-wide ZScale interval and draws labeled native-scale panels under `output/runs/<run-id>/previews/`. Preview paths are included in reports and activity events; rendering does not participate in detection or crop selection.
