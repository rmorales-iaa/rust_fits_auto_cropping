# Project instructions

Always work and respond in English.

Read `input/doc/skills/scientific-fits-engineering/SKILL.md` before project work. It is the authoritative project contract. Read relevant sibling specialty skills when needed; no delegation is required.

Documentation lives in `input/doc/`. Runtime configuration lives in `input/`. Every invocation writes to a unique, validated `output/runs/<run-id>/` directory containing `images/`, `masks/`, optional `previews/`, `manifests/`, `summary.json`, `per-image.csv` and an ISO-named activity log. Atomically publish a per-input completion manifest only after the expected products are verified; version-3 manifests include source and per-product SHA-256 digests, and missing markers mean incomplete/failed output. Preserve previous runs; never clean or overwrite them implicitly. The output root and its managed path components must not be symlinks, and input/output trees must not overlap. An explicit output directory becomes the output root.

Keep the root README current. Tool-required Cargo files remain at the project root. Preserve unrelated work and automatically commit each verified, coherent change locally. Never push unless requested.

For current work read `input/doc/project-memory.md`, `input/doc/scientific-audit-2026-10-27.md` and the active `input/doc/scientific-improvement-plan.md`. The original implementation plan is historical; distinguish planned algorithms from implemented behavior. Keep candidate artifacts, original undefined pixels, crop sacrifices and ground-truth science validity separate. Passing engineering tests is insufficient for a scientific-release claim; apply the active plan's independent data, uncertainty, loss and performance gates.

The baseline implementation is recorded in `input/doc/implementation-plan.md`; future work follows `input/doc/scientific-improvement-plan.md`. Detection decisions use image pixel statistics; header cards do not serve as evidence, though structural/storage metadata is required to decode FITS samples and null values. Carry the parsed FITS source snapshot from classification into generated-product writing and verify against that same snapshot; do not reread a mutable input path for product pixels or expected data. Record SHA-256 of the bytes read through the same open source handle in the per-image report and completion manifest. The Rust CLI is `rust_fits_auto_cropping`; it supports single-HDU 2D integer and floating FITS images in dimension-preserving mask mode or opt-in crop mode, which selects the higher-area clean candidate between an exact axis-aligned rectangle and a conservative integer-centered circle and applies the configured sacrifice-versus-removal utility. Unchanged eligible images are symlinks under `output/runs/<run-id>/images/`; never modify their sources. Generated FITS products record program/version and UTC creation provenance. The tracked version template is `input/program-version.txt`, and ignored build state is `output/.state/program-version.txt`. Compressed FITS inputs are ignored. Check branches/remotes before authorized merge or push; never invent a remote URL. Do not claim the detector scientifically validated until it passes held-out observatory data review; threshold calibration remains outstanding.
