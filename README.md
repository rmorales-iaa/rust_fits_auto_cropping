# rust_fits_auto_cropping

A conservative Rust CLI prototype that detects large, anomalous regions connected to the borders of one-HDU, two-dimensional FITS images. It writes processed images with accepted samples marked undefined, a separate mask, symlinks unchanged images into the output tree, and creates a per-run report. Original files remain untouched. Detection is driven by pixel statistics; non-structural header content is not a detector feature.

The first detector uses robust tile statistics, spatial lag-one correlation and border-connected components. It supports asymmetric and partly symmetric border patterns; circle/rectangle boundaries are approximated at tile scale. Its thresholds are starting values and have **not** been scientifically validated against held-out observatory images. Inspect every mask before scientific use. See [the algorithm and its limits](input/doc/algorithm.md).

The [scientific audit](input/doc/scientific-audit-2026-10-27.md) found boundary over/under-removal, numerical scaling and integer-sentinel failures, and metadata/reporting gaps despite 47 passing tests. Follow-up fixes include conservative keep-source fallback when no integer BLANK value is available, refusal to crop unsupported lookup-table/distortion WCS, integer precision abstention, independent component gates, rescaled allocation-free correlation, exhaustive small-grid geometry oracles, source-byte digests, stable decision codes, and explicit C/A/E/U0 set accounting. Schema-8 reports include total and output-image counts plus the optional reason-plane path; the prior schema-6 accounting distinguishes candidate, proposed, applied-artifact and crop-geometry sets, including their intersections with original undefined pixels. The current source snapshot is carried from detection through output writing so classification, serialization and verification use one parsed input; version-3 completion markers include source and product SHA-256 digests. The opt-in `--reason-mask` product records retained pixels, detector-selected artifact exclusions, crop-only sacrifices and pre-existing undefined samples. Its codes are action bookkeeping, not ground-truth science labels. These are engineering improvements, not scientific validation: tile-scale boundary error remains, a source-aware local model and pixel refinement remain unimplemented. The opt-in robust-affine reference and multiscale-consensus detector are experimental; thresholds have no independent calibration. See the [active improvement plan](input/doc/scientific-improvement-plan.md) and [validation record](input/doc/validation.md). Cargo package version `0.1.0` and the machine-local `--version` build counter identify different things; neither is a scientific certification.

## Build and run

Requires Rust 1.88+. FITS reading and writing use the pure-Rust [`fitskit`](https://docs.rs/fitskit/) crate and do not require CFITSIO or a system C library.

```bash
cargo build --release
cargo run --release -- --input-dir input/data --output-dir output --config input/config.toml
cargo run --release -- --input-dir input/data --output-dir output --recursive --config input/config.toml --heuristics input/heuristics.toml
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --recursive
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --png --recursive
cargo run --release -- --input-dir input/data --output-dir output --dry-run
```

Pass `--help` for options, examples, crop semantics and exit codes. `--version` reports the build counter. The output root is canonicalized and checked before use; a symlinked root, overlapping input/output trees, unsafe relative destinations or symlinked managed subdirectories are rejected. Previous run data are preserved. By default only the immediate input directory is searched; use `--recursive` for nested folders. Multi-HDU files and unsupported shapes/compressed inputs are recorded as ignored. Corrupt files and inputs exceeding the configured memory limit are recorded as errors. In normal runs, every discovered FITS path has one corresponding `images/` entry: malformed and ignored inputs are annotated and passed through as symlinks to their originals. Dry-run writes no image entries.

## Products and configuration

Each run is stored beneath `output/runs/<run-id>/`, with `images/`, `masks/`, optional `reason_masks/` and `previews/`, `manifests/`, `summary.json`, `per-image.csv` and an ISO-dated `activity_*.jsonl` together. `summary.json` reports `total` discovered inputs and `output_images` published image entries. For a successful normal run these counts match; failed symlink publication is reported as an error and visible in the count. Science and mask products are built and verified in temporary sibling directories before being published; ordinary rename failures roll back the pair. A `manifests/<input-relative-path>.complete.json` marker is atomically published after that input's products have been verified, including pass-through symlinks for malformed or ignored inputs; absent markers identify incomplete or failed output. A process or power failure between final file renames can still leave an unmanifested partial set. Previous markers are invalidated before an explicit overwrite. Existing run directories are preserved. Output-root symlinks, input/output overlap, unsafe relative paths and symlinked product subdirectories are rejected before product writes. Output symlinks target canonical input files and preserve original bytes and headers. Generated FITS products record program/version in `CREATOR`, UTC product date in `DATE`, and generation time in bounded `HISTORY` cards. The tracked `input/program-version.txt` template begins at `0.0.0`; each Cargo package recompilation increments the build version in base 100. A no-op Cargo invocation does not advance it. Mask mode preserves dimensions. Crop mode (`--mode crop`) compares the maximum-area clean rectangle with a conservative pixel-mask-derived circle. If the circle contains more clean pixel centers, crop mode writes the exact maximum-area axis-aligned rectangle wholly inside it; otherwise it writes the unrestricted maximum clean rectangle. Detector-proposed and originally undefined pixels are excluded from both candidates. FITS `NAXIS1/2` match the output rectangle width and height, and supported primary/alternate `CRPIX1/2` values shift by the crop origin. Circular fields therefore produce rectangular/square crops with no newly undefined corner pixels, at the cost of retaining fewer samples than a circular product. The configured utility remains provisional and is not a calibrated science loss model, and it can keep the original when crop losses outweigh the heuristic benefit. Integer image pixels use FITS `BLANK` when a representable value is available; float pixels use NaN. Retained raw samples and checksums are verified against the same parsed FITS snapshot used for detection.

Reports distinguish edge-tile candidate support (`candidate_mask_pixels`), accepted proposals (`proposed_mask_pixels`), and applied artifact exclusions (`applied_artifact_pixels`). `masked_pixels` includes all newly excluded defined samples, including crop-only geometric sacrifices. `crop_excluded_undefined_pixels` records originally undefined samples inside the proposed crop exclusion; it is kept separate from both scientific artifact removal and sacrificed defined pixels. Schema 8 records input/output counts, candidate/proposed/applied intersections with original undefined pixels, candidate/proposal overlap, crop geometry intersections, and proposed-versus-applied crop accounting. Stable `reason_code` values support machine-readable decisions alongside explanatory text. Dry runs set the top-level `dry_run` flag and report zero applied exclusions and zero output images. Independent artifact labels and science validation remain future work.

With `--mode crop --png`, `output/runs/<run-id>/previews/<input-relative-path>.png` is written for each accepted crop. Each RGB preview places the complete grayscale input at left and the unchanged grayscale crop at right using one source-derived ZScale interval, native pixel scale, labeled panels and FITS lower-origin orientation. A green line outlines the pixels retained by the crop; a red line marks the adjacent excluded/cropped pixels on the left panel. Previews are diagnostic only; the FITS output remains the science product, and each preview path appears in the report.

Pass `--reason-mask` to write an optional `reason_masks/<input-relative-path>` byte image for each accepted mask/crop action. Codes `0` retained defined sample, `1` detector-selected artifact exclusion, `2` crop-only sacrifice of a defined sample, and `3` originally undefined sample. Undefined samples take precedence. The sidecar preserves compatible WCS cards, has `RSCHEME=PIXACT1`, and is verified and checksummed in the completion manifest. These codes describe program actions, not astrophysical validity or calibrated confidence.

Operational settings live in [input/config.toml](input/config.toml), and science decision rules live in [input/heuristics.toml](input/heuristics.toml). Read the [user guide](input/doc/user-guide.md), [configuration reference](input/doc/configuration.md), [architecture](input/doc/architecture.md), [algorithm limits](input/doc/algorithm.md), [build and provenance policy](input/doc/release-and-provenance.md), [validation record](input/doc/validation.md), and [project memory](input/doc/project-memory.md). Crop mode is opt-in and can discard unmasked science pixels; check each report before downstream use. Gzip-compressed and multi-HDU inputs are ignored.

## Project development

Source code is organized in small modules under `src/`; tests are under `tests/`. Run `cargo test --all-targets`, `cargo fmt --all --check`, and `cargo clippy --all-targets -- -D warnings`. The independent FITS checker is `tools/cross_validate_fits.py`; it requires Astropy and runs `fitsverify` when available. It checks reason-code planes against source undefined pixels and action masks, audits preserved/added FITS cards, and exercises primary/alternate WCS. Run its Python regression tests with `python3 -m unittest tools/test_cross_validate_fits.py`. `tools/cross_validate_previews.py` requires Astropy and Pillow to validate PNG scaling, green/red overlay geometry and colors, orientation and source/crop display samples. Each verified coherent change is registered in local Git. Build products, logs and raw FITS inputs are ignored. A local branch commit does not publish without a configured remote and explicit push.
