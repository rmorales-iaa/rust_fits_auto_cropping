# Architecture

The application keeps CLI parsing, typed configuration, file discovery, FITS access, robust statistics, border detection, output writing, logging and summary generation in separate Rust modules. The algorithm module consumes a row-major floating analysis array and returns a boolean mask plus diagnostics; FITS code has no role in deciding whether a region is scientifically invalid.

The pure-Rust `fitskit` crate parses and serializes FITS files. A header-only preflight seeks over payloads to count HDUs and reject unsupported or oversized files before allocating pixel arrays. Descriptive header values are not detector inputs; structural, storage-scaling and null metadata are interpreted or validated as required by the FITS representation. Scaling cards are not applied to detector statistics. Each accepted file is independently owned by one worker; no shared FITS handles or global FITS lock are needed. Directory jobs run in a bounded Rayon pool, so independent detection and FITS work can overlap. Memory is bounded by weighted admission (`src/memory.rs`). After the header preflight, and before any pixel buffer is allocated, each image reserves its estimated peak from the shared `memory_budget_mib` and holds it until it is dropped. The estimate is pixels × (stored bytes + 8 + detector overhead + preview overhead) + 64 MiB, an upper envelope fitted to measured peak RSS of release runs. Workers follow the CPU setting only. With six 37.8-Mpx frames, 4 workers and a 2,500 MiB budget, peak RSS was 1,430 MiB (two images at a time). The estimate is not a hard RSS guarantee.

For integer arrays, `fitskit` exposes stored samples directly. Detection uses median-centered raw integer values formed with i128 differences; it abstains when an integer span cannot be represented exactly in the f64 analysis domain. Floating samples are centered by a finite median with overflow-safe fallback arithmetic. `BSCALE/BZERO` remain in copied science headers but are not applied to detector values. The parsed source `FitsFile` is retained in the `Image` result and is the source for generated products, eliminating later source-path reparsing and ensuring classification, written samples and in-process verification refer to one snapshot. The writer reuses a valid existing integer `BLANK` and otherwise searches for a code absent from retained samples only when a product adds undefined pixels. If no integer code is available, processing keeps the input as an unchanged symlink. Floating exclusions use IEEE NaN. The binary action mask is verified in memory against the written science array (masked samples undefined, retained samples identical); no mask sidecar file is written (plan R0.5). Generated science products add only `MO_` provenance cards (`MO_ACT`, `MO_CROP`, `MO_UNDF`, `MO_ALGO`, `MO_PROG`, `MO_DATE`, `MO_SHA`, `MO_FILE`, and for crops `MO_SEC`, `MO_ONAX1/2`, `MO_X0/Y0`); a full-frame rectangle is never written as a crop. Publication writes and fsyncs the product, re-reads it once from disk, verifies its DATASUM, and runs the sample and header checks on that on-disk snapshot. Unchanged images are symlinks and preserve source bytes. Science products are not re-serialized by the crate: the source header's original 80-byte cards, captured from the same hashed read, are copied verbatim with only the documented edits (`src/writer/product_header.rs`), and the data unit is the big-endian encoding of the selected samples. FITS checksums and semantic sample comparisons are verified against the retained snapshot; ordinary failures attempt rollback. When lookup-table or recognized distortion metadata cannot be safely shifted, crop mode applies accepted detections as a dimension-preserving mask (`crop_wcs_mask_fallback`). Full WCS support remains open.

Generated science products are written and verified in a sibling staging directory and atomically renamed into place; a symlinked destination is refused. Unchanged kept images are staged as symlinks on the output filesystem and atomically published; the symlink target is the canonical input path. Parsing and source hashing use the same open file handle: the digest is calculated as fitskit reads the stream, including block padding skipped by forward seeks, with bounded memory. A size/modified-time change during parsing is rejected. After verification and any requested preview, per-input output paths and outcomes are recorded in the run summary and activity log. The application does not create a `manifests/` directory or per-input completion-marker files; consumers should use the final `summary.json` to assess completed outputs. Reports are sorted by relative input path so scheduling does not affect their record order.

The initial detector operates on fixed-size tiles. It obtains robust median and MAD summaries, estimates an interior reference, computes allocation-free lag-one spatial correlation with rescaled Welford moments, flags high-contrast tiles supported by correlation or unusually low noise, then labels 4-connected edge components. Each component must independently clear tile-count, area, evidence and provisional utility gates before its tiles are accepted. Final aggregate area and utility checks still apply. Reports record candidate and accepted component counts. Component labeling prevents disconnected regions from borrowing support, but does not provide multiscale evidence, source protection, calibrated statistics, or pixel-level boundaries. Accepted tiles still expand to whole tiles. This remains a first-pass heuristic, not a trained/calibrated classifier; domain-specific validation remains open.

When requested with `--png` in crop mode, a post-decision renderer uses the Rust `image` crate's PNG encoder. It estimates one source-wide ZScale interval and draws labeled native-scale panels under `output/runs/<run-id>/previews/`. Preview paths are included in reports and activity events; rendering does not participate in detection or crop selection.

The default output layout isolates each invocation under `runs/<run-id>/` and stores science images in `images/`. The opt-in `--flat-output` layout sets the run root to the requested output root, stores science image files directly there, and continues to place previews under `previews/`. Reports and the activity log remain at the root. The yearly storage script uses this flat layout for its fixed per-year destination.

## Action selection and v2 detector modules (Revision 2 implementation)

`src/action.rs` turns a detection into one product action (keep, mask, crop, crop_masked, bbox_mask) with a single pixel accounting, and `src/pipeline/decoded.rs` writes the chosen product. Crop candidates are evaluated through a shared summed-area `SearchContext` in `src/crop.rs`; `src/crop/global_search.rs` adds the global row-pair/column-sweep family. Detection tile statistics use exact O(n) selection on reusable scratch buffers and are evaluated per tile row in parallel with ordered collection, so results are identical for any worker count.

The default v2 detector (decision D5) lives in `src/detection/v2/`: `background.rs` (meshes, trusted-cluster selection, Huber surface, noise grids, AR(1)), `noise.rs` (second-difference noise), `sources.rs` (source mask, FWHM), `evidence.rs` (tile scores, rules, components, change-point test), `distance.rs` (exact banded signed distance; full EDT kept as a test oracle), `refine.rs` (hysteresis boundaries) and `bitset.rs`. Per-row and per-mesh loops run in parallel with ordered collection. `calibration_tests.rs` holds the ignored null-false-alarm and injection harness.
