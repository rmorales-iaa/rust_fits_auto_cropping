# rust_fits_auto_cropping

A conservative Rust CLI prototype that detects large, anomalous regions connected to the borders of one-HDU, two-dimensional FITS images. It writes processed images (dimension-preserving masks, rectangular crops, crops with masked interiors, or bounding-box crops with masked flags), symlinks unchanged images into the output tree, and creates a per-run report. Original files remain untouched. Detection is driven by pixel statistics; non-structural header content is not a detector feature.

The default detector (`background_v2`, decision D5) fits a source-masked mesh background and noise model, scores border tiles with two-sided standard-error evidence and a D4 minimum-effect test, protects astronomical sources, requires a boundary change-point for deficit-only regions, and refines boundaries at native resolution. On seeded synthetic data it has zero false alarms in 14 null family/size cells (Clopper–Pearson bound ≤ 1e-3 at 256 px) and recall ≥ 0.96 on strips and field stops ([validation](input/doc/validation.md)). Its thresholds are registered starting values and have **not** been validated against held-out observatory images (gate G4 is open). Inspect every product before scientific use. The legacy tile detector remains selectable with `detector = "tile_v1"`; it uses robust tile statistics, lag-one correlation and border-connected components at tile resolution. See [the algorithm and its limits](input/doc/algorithm.md).

The [scientific audit](input/doc/scientific-audit-2026-10-27.md) found boundary over/under-removal, numerical scaling and integer-sentinel failures, and metadata/reporting gaps despite 47 passing tests. Follow-up fixes include conservative keep-source fallback when no integer BLANK value is available, dimension-preserving mask fallback when lookup-table/distortion WCS prevents a safe crop, integer precision abstention, independent component gates, rescaled allocation-free correlation, exhaustive small-grid geometry oracles, source-byte digests, stable decision codes, and explicit C/A/E/U0 set accounting. Schema-9 reports include total and output-image counts plus the optional reason-plane path; the prior schema-6 accounting distinguishes candidate, proposed, applied-artifact and crop-geometry sets, including their intersections with original undefined pixels. The current source snapshot is carried from detection through output writing so classification, serialization and verification use one parsed input; per-image reports include source SHA-256 digests; per-input completion markers are not generated. The opt-in `--reason-mask` product records retained pixels, detector-selected artifact exclusions, crop-only sacrifices and pre-existing undefined samples. Its codes are action bookkeeping, not ground-truth science labels. These are engineering improvements, not scientific validation: tile-scale boundary error remains, a source-aware local model and pixel refinement remain unimplemented. The opt-in robust-affine reference and multiscale-consensus detector are experimental; thresholds have no independent calibration. See the [active improvement plan](input/doc/scientific-improvement-plan.md) and [validation record](input/doc/validation.md). Plan Revision 2 (2026-10-29) records new synthetic counterexamples for the default detector: decisions depend on unrelated interior sources, flat-amplified borders are missed, and edge sources or smooth vignetting are removed. It also sets out the R0–R6 roadmap: exact-selection and I/O speedups, a source-masked background/noise model, two-sided evidence calibrated by null false-alarm rate, native-resolution boundaries, exact tolerant-rectangle search and hybrid crop/mask actions, plus flat-derived evaluation labels. Defaults are unchanged pending user decisions D1–D4. Cargo package version `0.1.0` and the machine-local `--version` build counter identify different things; neither is a scientific certification.

## Build and run

Requires Rust 1.88+. FITS reading and writing use the pure-Rust [`fitskit`](https://docs.rs/fitskit/) crate and do not require CFITSIO or a system C library.

```bash
cargo build --release
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop_masked --recursive
cargo run --release -- --input-dir input/data --output-dir output --config input/config.toml
cargo run --release -- --input-dir input/data --output-dir output --recursive --config input/config.toml --heuristics input/heuristics.toml
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --recursive
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --flat-output --recursive
cargo run --release -- --input-dir input/data --output-dir output-crop --mode crop --png --recursive
cargo run --release -- --input-dir input/data --output-dir output --dry-run
```

Pass `--help` for options, examples, crop semantics and exit codes. `--version` reports the build counter. The output root is canonicalized and checked before use; a symlinked root, overlapping input/output trees, unsafe relative destinations or symlinked managed subdirectories are rejected. Previous run data are preserved unless `--sanitize-output` is explicitly selected. By default only the immediate input directory is searched; use `--recursive` for nested folders. Multi-HDU files, unsupported shapes and compressed inputs remain ignored because their pixel arrays are not accepted by the current processing contract. A valid decoded image is always checked by pixel statistics regardless of descriptive/WCS header cards. Source header cards are never repaired: malformed non-structural cards are substituted only in the parser's temporary in-memory view, annotated in the summary, and copied byte-for-byte into generated FITS products while pixels are processed. Crop dimensions and product provenance are updated as required, but those operations do not normalize malformed source cards. Structural layout cards such as BITPIX and NAXIS must remain readable to locate pixel data. If lookup-table WCS prevents a safe rectangular crop, the summary records that metadata limitation and accepted border detections are applied as a dimension-preserving full-frame mask. Inputs with unreadable structural layout or those exceeding the configured memory limit are recorded as errors. In normal runs, every discovered FITS path has one corresponding image product: under `images/` by default or directly under the output root with `--flat-output`. Malformed structural files and ignored inputs are annotated and passed through as symlinks to their originals. Dry-run writes no image entries.

## Yearly calibrated-image workflow

[`scripts/process_cropped_years.sh`](scripts/process_cropped_years.sh) creates `/mnt/uxmal_groups/image_storage/cropped/<year>/`, links the `bias/`, `dark/`, and `flat/` directories from `rust_om_cal`, and processes `science_calibrated/` recursively in crop mode with PNG previews enabled. It shows a per-year progress bar driven by completed FITS files. Before each year run, `--sanitize-output` clears the contents of only its dedicated `science_calibrated/` destination. FITS products and reports go directly under that path; previews remain in its `previews/` directory, with no `images/` or `runs/<run-id>/` layer for current products. Test one year with `scripts/process_cropped_years.sh --year 2002`; with no arguments it processes years 2002 through 2026. Other selections:
- repeat `--year`;
- `--years 2009,2011,2017` for a list;
- `--from 2009 --to 2012` for a range.

`--mode crop|crop_masked|mask` and `--heuristics PATH` (for example a rule copy selecting the legacy `tile_v1` detector) are passed through; `--no-png` disables previews. `--plan` validates paths and prints FITS counts and sanitation targets without writing or deleting anything.

Safety:
- The script refuses relative, filesystem-root, identical or nested source/output roots and symlinked output directories.
- An exclusive lock (`OUTPUT_ROOT/.process_cropped_years.lock`) prevents two batches from sanitizing the same storage.
- Ctrl-C or TERM stops the crop process itself; earlier versions left it running.

After each year it prints input/output counts, clipped/kept/ignored/error totals, the parity check and the elapsed time, and finally a per-year status. Exit status: 1 marks years that failed, were incomplete, or completed with preserved malformed inputs.

Existing non-symlink calibration destinations and links that point elsewhere are left untouched and reported as errors. Run `bash scripts/test_process_cropped_years.sh` for its mock-based regression tests (42 checks).

## Products and configuration

Image processing is parallelized with a bounded Rayon worker pool. Set `processing.threads` in `input/config.toml` to `4` (default) or `0` to request all logical CPUs available to the process; CPU and memory limits can reduce the effective count. The activity log records the effective number of workers.

By default each run is stored beneath `output/runs/<run-id>/` with science images in `images/`. `--flat-output` writes science images directly under the given output directory instead, for workflows that require a fixed destination such as `/mnt/uxmal_groups/image_storage/cropped/2002/science_calibrated/`; previews remain in `previews/`, and reports and logs remain in the root. `--sanitize-output` explicitly deletes every existing entry in the output root before processing, and is used by the yearly workflow only on its dedicated science-output directory. `previews/` is optional and created only when `--png` is enabled and a crop is accepted. There is no `manifests/` directory or per-input completion marker; the final summary and activity log record per-input decisions and output paths. Action masks are verified in memory, so no `masks/` directory is written; temporary `reason_masks/` (only with `--reason-mask`) are removed before reports are written and before exit. `summary.json` reports `total` discovered inputs and `output_images` published image entries; for a successful normal run these counts match. Previous run directories are preserved in the default layout unless `--sanitize-output` is explicitly selected. Output-root symlinks, input/output overlap, unsafe relative paths and symlinked product subdirectories are rejected before product writes. Output symlinks target canonical input files and preserve original bytes and headers. Generated FITS products keep the source header cards verbatim and record program/version and UTC creation time in `MO_PROG`/`MO_DATE` (see Product headers below). The tracked `input/program-version.txt` template begins at `0.0.0`; each Cargo package recompilation increments the build version in base 100. Mask mode preserves dimensions. Crop mode (`--mode crop`) starts from the exact maximum-area axis-aligned rectangle containing no detector-proposed artifacts or originally undefined samples, then may enlarge it within a bounded search while retaining at most the configured residual fraction of detector-flagged samples (0% shipped, so a crop never keeps flagged samples as data). Originally undefined samples are never retained. Candidates come from an anchor-expansion family and a global row-pair/column-sweep family (exact for the area objective at row step one); the better feasible rectangle is kept. `--mode crop_masked` selects its rectangle the same way, may enlarge it over up to 5% flagged samples (`crop_masked_residual_fraction`), and writes retained detector flags as BLANK/NaN. When no rectangle passes the gates, `heuristics.crop_fallback` selects the action: the shipped `bbox_mask` crops to the bounding box of retained unflagged samples and marks the remaining flags undefined (all flags removed, no valid-pixel sacrifice); `keep` remains the default for rule files without the key. Results are not constrained by a circular fit. Accepted crop FITS filenames add `_cropped` before the extension; kept and pass-through images keep their original names. FITS `NAXIS1/2` match the selected rectangle width and height, and supported primary/alternate `CRPIX1/2` values (and existing `LTV1/2`) shift by the crop origin. The configured utility remains provisional and is not a calibrated science loss model.

Shipped crop limits (plan Revision 3; chosen on a synthetic policy grid and confirmed on a held-out synthetic corpus, not yet on observatory data): a crop may discard at most 10% of unflagged defined pixels (`maximum_crop_sacrifice_fraction`) and at most one unflagged pixel per two flagged pixels removed (`crop_exchange_rate = 0.5`). An optional per-border-area-count cap table is still accepted for older rule files. The utility gate can also reject a proposed crop, in which case the fallback applies. On the held-out corpus, crop mode had recall 0.992, precision 0.985 and valid loss 0.27%; the previous 35–47% tiered caps gave 0.850, 0.812 and 3.5% ([validation](input/doc/validation.md#revision-3-evidence-2026-10-29)). Integer image pixels use FITS `BLANK` when a representable value is available; float pixels use NaN. Retained raw samples and checksums are verified against the same parsed FITS snapshot used for detection.

**Product headers.** A generated science product keeps the source primary header exactly as it was: every original 80-byte card is copied byte for byte and in order, including `DATE`, `CREATOR`, `HISTORY`, `COMMENT`, `DATAMIN`/`DATAMAX` and malformed cards. The only edits are:

- `NAXIS1`/`NAXIS2` (crop dimensions);
- `CRPIX1/2` and alternate `CRPIXna` (shifted by the crop origin so the WCS stays correct), and `LTV1`/`LTV2` only when the source already has them (IRAF physical coordinates);
- `BLANK`, only when integer samples are newly set undefined;
- `CHECKSUM`/`DATASUM`, recomputed.

Everything the program adds is an `MO_` keyword, on every product:

| Card | Meaning |
| --- | --- |
| `MO_ACT` | Product action: `mask`, `crop`, `crop_masked` or `bbox_mask`. |
| `MO_CROP` | `T` when the image is cropped relative to the original frame, `F` otherwise. Select cropped images with `MO_CROP = T`. |
| `MO_SEC` | Crops only: kept section of the original image in IRAF/FITS section syntax `[x1:x2,y1:y2]` (1-based, inclusive). |
| `MO_ONAX1`, `MO_ONAX2` | Crops only: original image dimensions; a calibration frame must match them. |
| `MO_X0`, `MO_Y0` | Crops only: zero-based origin of the section in the original image. |
| `MO_UNDF` | Samples set undefined by this product. |
| `MO_ALGO` | Detector algorithm ID. |
| `MO_PROG`, `MO_DATE` | Program/version and UTC creation time. |
| `MO_SHA`, `MO_FILE` | SHA-256 and base name of the original file (`MO_FILE` is omitted when the name does not fit on a card). |

Re-cropping an already cropped product expresses `MO_SEC` in the original frame's coordinates and keeps the original identity. Kept images are symlinks and carry no cards at all. Full-frame rectangles are applied as masks (reason `crop_full_frame_mask`). The writer verifies every product on disk: preserved cards byte-identical and in order, edited values as expected, the exact `MO_` cards, samples, and checksums. Section cards such as `DATASEC`, `TRIMSEC`, `BIASSEC` and `CCDSEC` are part of "as it was": they are not edited and still refer to original coordinates.

To give calibration frames the same geometry, run `python3 tools/apply_crop.py --reference SCIENCE_cropped.fits --output-dir OUT bias.fits dark.fits flat.fits`. It applies the same header rule, copies the stored sample bytes of the section unchanged, and adds `MO_` cards with `MO_REF` set to the science frame's `MO_SHA`. It refuses frames whose size differs from `MO_ONAX1/2` or that are already cropped. It writes Astropy-compatible checksums, verifies the result and never modifies its inputs.

Reports distinguish edge-tile candidate support (`candidate_mask_pixels`), accepted proposals (`proposed_mask_pixels`), and applied artifact exclusions (`applied_artifact_pixels`). `masked_pixels` includes all newly excluded defined samples, including crop-only geometric sacrifices. `crop_excluded_undefined_pixels` records originally undefined samples inside the proposed crop exclusion; it is kept separate from both scientific artifact removal and sacrificed defined pixels. Schema 12 records input/output counts, the selected action, crop geometry and accounting (including interior-masked pixels), residual-flag fraction, rectangle-search diagnostics, v2 uncertain-boundary and protected-source pixel counts, and per-stage timings. `maximum_residual_artifact_fraction` in `input/heuristics.toml` bounds the fraction of detector-flagged, defined pixels a crop may keep as data; the shipped value is 0, and `crop_masked_residual_fraction` (5% shipped) applies to `crop_masked`, which writes those pixels undefined. Stable `reason_code` values support machine-readable decisions alongside explanatory text. Dry runs set the top-level `dry_run` flag and report zero applied exclusions and zero output images. Independent artifact labels and science validation remain future work.

Previews are disabled by default. With `--mode crop --png`, `output/runs/<run-id>/previews/<input-relative-path>.png` is written for each accepted crop. Each RGB preview places the complete grayscale input at left and the unchanged grayscale crop at right using independent ZScale intervals computed from the full input and the exact final cropped FITS samples, labeled panels and FITS lower-origin orientation. The crop panel is uniformly scaled with nearest-neighbor sampling to fill its display height while preserving aspect ratio; its `CROP FIT` label marks that its displayed pixel scale can differ. A green line outlines the pixels retained by the crop; a red line marks the adjacent excluded/cropped pixels on the left panel. The crop panel contains only the crop image; no blank canvas rows are added. Previews are diagnostic only; the FITS output remains the science product, and each preview path appears in the report.

Pass `--reason-mask` to build and verify a temporary byte image for each accepted mask/crop action. Its containing `reason_masks/` directory is removed before the run completes, so no sidecar path or checksum is published. `RSCHEME=PIXACT2`: code `0` is retained defined unflagged input, `1` detector-selected artifact exclusion, `2` crop-only sacrifice, `3` originally undefined input, and `4` detector-flagged input retained inside a tolerant crop. Undefined samples take precedence. These codes describe program actions, not astrophysical validity or calibrated confidence.

Operational settings live in [input/config.toml](input/config.toml), and science decision rules live in [input/heuristics.toml](input/heuristics.toml). Read the [user guide](input/doc/user-guide.md), [configuration reference](input/doc/configuration.md), [architecture](input/doc/architecture.md), [algorithm limits](input/doc/algorithm.md), [build and provenance policy](input/doc/release-and-provenance.md), [validation record](input/doc/validation.md), and [project memory](input/doc/project-memory.md). Crop mode is opt-in and can discard unmasked science pixels; check each report before downstream use. Gzip-compressed and multi-HDU inputs are ignored.

## Project development

Source code is organized in small modules under `src/`; tests are under `tests/`. Run `cargo test --all-targets`, `cargo fmt --all --check`, and `cargo clippy --all-targets -- -D warnings`. The independent FITS checker is `tools/cross_validate_fits.py`; it requires Astropy and runs `fitsverify` when available. It audits retained science images, reports, preserved/added FITS cards, and primary/alternate WCS; transient action-mask sidecars are intentionally absent after a run. Run all Python regression tests with `python3 -m unittest discover -s tools -p "test_*.py"`. `tools/make_synthetic_corpus.py` writes seeded fixtures with exact V/I/Q/U0 truth; `tools/flat_labels.py` derives evaluation labels from matched master flats (decisions D3/D4); `tools/evaluate_masks.py` reconstructs removed pixels from products and reports recall, precision, valid loss and residual contamination with group-bootstrap intervals. `tools/make_out_of_model_nulls.py` writes artifact families the corpus generator does not model (cosmic rays, trails, saturated edge stars, hot columns, crowded edges, and labelled corner glow and light leaks). `tools/shadow_compare.py` stratifies two detectors' runs and draws a labelling sample with recorded inclusion probabilities, then gives Horvitz–Thompson estimates and the plan's rollback check (R5.0). `tools/drift_monitor.py` flags years whose action, abstention or error rates depart from the other years (exact binomial tests, Holm control; R5.2). `tools/apply_crop.py` applies a product's crop to calibration frames. The ignored Rust harnesses `cargo test --release --locked calibration -- --ignored --nocapture` (null false alarms, injection recovery), `v1_v2_comparison` and `equivalence_harness` reproduce the validation evidence. `tools/cross_validate_previews.py` requires Astropy and Pillow to validate PNG scaling, green/red overlay geometry and colors, orientation and source/crop display samples. Each verified coherent change is registered in local Git. Build products, logs and raw FITS inputs are ignored. A local branch commit does not publish without a configured remote and explicit push.
