# Architecture

The application keeps CLI parsing, typed configuration, file discovery, FITS access, robust statistics, border detection, output writing, logging and summary generation in separate Rust modules. The algorithm module consumes a row-major floating analysis array and returns a boolean mask plus diagnostics; FITS code has no role in deciding whether a region is scientifically invalid.

The pure-Rust `fitskit` crate parses and serializes FITS files. A header-only preflight seeks over payloads to count HDUs and reject unsupported or oversized files before allocating pixel arrays. Descriptive header values are not detector inputs; structural, storage scaling and null metadata are required for decoding. Each accepted file is independently owned by one worker; no shared FITS handles or global FITS lock are needed. Directory jobs run in a bounded Rayon pool, so independent detection and FITS work can overlap. Workers are limited by `memory_budget_mib / maximum_image_mib`; the configured estimate has not been established as a peak-memory upper bound, especially for crop/write/verification/PNG stages.

For integer arrays, `fitskit` exposes the stored samples directly. The reader subtracts a robust raw integer anchor in i128 before conversion to f64 for detection, which can preserve small differences at large raw integer offsets, but currently re-adds BZERO; a sufficiently large BZERO can erase these differences again. The writer keeps retained raw pixel codes and uses an existing BLANK value or finds an unused in-range code for rejected integer samples. Floating images use IEEE NaN. A separate uint8 primary image stores the new mask and copies parsed non-structural source header cards, including WCS, while excluding data-scaling, dimension, summary and checksum cards. BUNIT is currently copied into masks, an incorrect unit policy identified in the audit. Generated science/mask products receive `CREATOR`, `DATE`, and timestamped `HISTORY` provenance. Unchanged images are symlinks and therefore preserve their source headers byte-for-byte. The crate rewrites parsed headers during serialization, so card values/order are retained by its header model but byte-for-byte card formatting is not promised for generated products. Temporary FITS data sums are checked before publishing; full semantic sample comparisons occur after publication and ordinary failures attempt rollback.

Generated science and mask products are written to temporary paths and renamed into place. Unchanged kept images are staged as symlinks on the output filesystem and atomically published; the symlink target is the canonical input path. The published science output is reopened to check one HDU, dimensions/BITPIX, retained samples, null representation and data sums. A process interruption can occur before this post-publication validation or pair rollback completes. If mask publication fails after science image publication, the partial image is removed. Reports are sorted by relative input path so scheduling does not affect their record order.

The initial detector operates on fixed-size tiles. It obtains robust median and MAD summaries, estimates an interior reference, computes lag-one spatial correlation, flags high-contrast tiles supported by correlation or unusually low noise, then flood-fills only edge-connected candidates. A mask is accepted only when it clears area and total-fraction gates. This is a first-pass heuristic, not a trained/calibrated classifier; domain-specific validation remains open.

When requested with `--png` in crop mode, a post-decision renderer uses the Rust `image` crate's PNG encoder. It estimates one source-wide ZScale interval and draws labeled native-scale panels under `output/runs/<run-id>/previews/`. Preview paths are included in reports and activity events; rendering does not participate in detection or crop selection.
